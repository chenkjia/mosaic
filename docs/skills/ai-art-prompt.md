# AI 出图 Prompt 写法与守卫

AI 出图任务（UI、立绘、卡面、图标、序列帧）出 prompt 前通读本文。规则源自 UI 复刻与 51+ 张批量立绘生产的实测沉淀（完整先例：sanguoV2 `docs/art/AGENTS.md` 与 `docs/skills/卡牌立绘生成.md`）；资源入库与交付要求见 `assets/art/AGENTS.md`。

## 先设计后出图

每张（批）图先写设计说明再出图，硬性顺序：构图与分区、要素清单、配色、负面清单。批量生产前先出试样经用户确认。

## 布局稿 → 风格稿 两段式

- 布局稿用中性扁平占位（flat UI mockup），只表达占比、层级与真实文案；风格元素一律留给风格稿。
- 布局稿经确认后即为铁律：风格稿正文必须逐字保留布局稿的结构句（「仅下沿」「无框」「恰好 N 张」类约束句），风格词只落在安全载体（页面背景、HUD 长条、按钮、卡片、徽章、文字）。
- 风格词与布局冲突时删风格词；负面清单须含框框类项（四周描边、悬浮面板、底板、托板、区块分割线）。

## 段落自包含

- 每段 prompt 完整自包含：布局、尺寸、数量、风格、负面词全部写进段内，用户可整段直接复制。
- 多风格/多变奏时，相同信息不抽取共用节，逐段重写——文档冗长可接受，拼装成本不可接受。

## 尺寸与数量写法

- prompt 正文用「px + 屏占比」双写描述尺寸与位置（如「高 84 像素（约画面高度 6%）」）；坐标表是核对真值，冲突时以坐标表为准。
- 组件/卡内的元素结构必须写进 prompt（名牌、立绘区、数值、技能条等按需求层级列出），删元素会出「空卡」；卡内不用百分比链（碎元素与尺寸漂移的来源），卡间尺寸用「绝对占比 + 倍数关系」双锚（如「宽约画面 17%，约为大卡的五分之二」）。
- 各区块元素数量用「恰好 N 张」显式声明并在 prompt 结尾复述总数；数量类错误对应项进负面清单。

## 对抗训练先验

- 受先验影响的元素必须补绝对锚点，并把漂移目标写进负面清单。典型：CTA 按钮默认被画到页面底部——补「位于画面高度约 N% 处」+ 负面清单写「按钮位于页面底部」。
- prompt 正文不写与出图无关的修饰（图标语义、装饰性形容、边缘对齐细节）；不描述交互行为与动效。

## 负面清单纪律

- 只留实际发生过的漂移项与高频伪影；臆测的低频项会稀释权重，不加。
- 默认包含 AI 伪影：`×`/关闭按钮、右上角关闭图标、水印、点击光标。

## 出图不符时的归因

先分辨口径错还是 AI 漂移，处置完全不同：

- **口径错**（spec / demo / prompt 三处说法不一致）：三处联动修改，口径统一后再出。
- **AI 漂移**（口径正确但模型画偏）：口径不动，只改 prompt 写法——补绝对锚点、负面清单加漂移位置。

## 批量生产防漂移

- **风格样板**：批量生成前，先产出少量试样（如吉凶两端各一）并经用户确认锁定风格；后续批次以试样为参考图。
- **身份锁**：同一对象跨所有产出保持不变的要素集合（脸部五官、发型冠饰、头身比体格、轮廓、核心识别符号、必留配件与配色 1 主 + 1 辅 + 1 点睛），一次定义、逐张校验；姿势、表情、朝向、持物方式为可变项。
- **程序化守卫**：可程序化检测的验收项一律脚本检测（主体触底占比、尺寸、水印区掩膜防误报、配色落点抽样），复检通过才算完成；不靠目检、不靠重出。检测失败优先程序化修复（如整体上移 + 渐变延伸，不缩放防发虚）或重出，修复后必须复检。
